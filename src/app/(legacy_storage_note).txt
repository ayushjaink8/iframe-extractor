
**Important Note on Data Storage for /render/[iframeId]**

The current implementation uses a Zustand store configured with `persist` middleware to manage the extracted iframe `srcdoc` data. This data is stored in `localStorage` under the key 'iframe-storage', allowing it to persist across browser tabs and sessions. The dynamic rendering page (`/render/[iframeId]`) accesses this store to retrieve the necessary `srcdoc` for display.

**Using Zustand with `localStorage` Persistence:**

1.  **State Management:** Zustand provides a clean way to manage application state.
2.  **Persistence:** The `persist` middleware automatically handles saving specified parts of the store (in this case, `id` and `srcdoc`) to `localStorage` and rehydrating the store when the application loads.
3.  **Cross-Tab Access:** `localStorage` allows data to be accessed by the `/render/[iframeId]` page even when opened in a new tab, provided it's the same browser and the data hasn't been cleared.
4.  **Size Limits:** `localStorage` still has size limitations (typically 5-10MB), which might be insufficient for very large or numerous `srcdoc` contents. Only essential data (`id`, `srcdoc`) is persisted to mitigate this.
5.  **Client-Side Dependency:** This approach still relies on client-side storage and hydration. Direct navigation to `/render/...` without the store being populated (e.g., after clearing browser data or in a different browser) will result in an error.

**Recommended Alternatives for a Production Application (Still Apply):**

While Zustand + localStorage is an improvement over direct localStorage manipulation, the following remain more robust solutions for production:

1.  **Server-Side Storage (Most Robust):**
    *   Store extracted `srcdoc` in a database (Firestore, PostgreSQL, etc.) associated with a unique ID upon file upload.
    *   The `/render/[iframeId]/page.tsx` (ideally a Server Component) fetches data directly from the database using `iframeId`.
    *   Most scalable and reliable approach, independent of client-side storage.

2.  **API Route Proxy (Alternative Server-Side):**
    *   Store data temporarily on the server (cache or temp DB).
    *   Create an API route (`/api/iframe/[iframeId]`) to serve the `srcdoc`.
    *   `/render/[iframeId]/page.tsx` fetches from this API route.

Zustand with localStorage persistence was implemented to improve state management while still quickly enabling the "Open in New Tab" feature without requiring a full backend database setup for this specific tool's context. A server-side storage solution is highly recommended for real-world applications requiring greater robustness and scalability.
